# Skill-Home Web 重构规格文档

## 1. 背景

当前 Web 前端已经具备宣传、搜索、发布、登录、控制台管理等基本能力，但整体仍是单页聚合结构，主要问题集中在：

- 信息架构混杂：宣传、发现、发布、管理混在同一页，用户任务流切换成本高。
- 视觉语言不统一：营销区、技能列表区、控制台区的层次关系不够稳定。
- 搜索体验偏弱：现有页面更像“展示页 + 简单筛选”，还不足以承担真正的技能中心。
- 安装引导偏分散：下载、pull、install 命令有了，但缺少面向不同 AI/IDE 的清晰分步指引。
- 代码组织不利于继续扩展：当前前端主要集中在单个入口组件中，不适合后续持续演进。

## 2. 重构目标

- 将 Web 从“单页宣传板”升级为“官网 + 技能中心 + 控制台”。
- 统一为扁平风设计，提升信息密度，同时保持专业、清晰、可信。
- 建立稳定的多页面信息架构，缩短用户从“浏览”到“安装”到“发布”的路径。
- 把技能中心做成核心流量入口，显著增强技能查找、筛选、理解和安装效率。
- 将 AI 安装指引产品化，支持一键复制和明确的后续动作提示。
- 通过路由、布局、组件拆分，为后续持续迭代打基础。

## 3. 设计原则

### 3.1 视觉方向

- 采用扁平风，不使用玻璃拟态、厚重阴影、悬浮装饰性大色块。
- 默认浅色主题，强调专业工具属性，而不是炫技展示页。
- 颜色系统采用语义 token：品牌色、边框色、文本层级、成功/警告/错误状态色。
- 视觉强调“清楚、紧凑、可信”，而不是“空灵、炫目、大片式”。

### 3.2 信息密度

- 列表和详情页改为高密度信息布局，优先展示关键信息：名称、命名空间、版本、扫描状态、更新时间、下载量、标签。
- 降低无效留白，增加列表信息颗粒度，允许卡片和表格式共存。
- 首页继续保留品牌表达，但压缩无效宣传内容，让核心动作更早出现在首屏。

### 3.3 交互原则

- 每个页面只承载一种主任务。
- 每个页面最多一个主 CTA，避免多个同级强操作抢焦点。
- 搜索、安装、发布、编辑都需要明确反馈，包括 loading、error、success、empty state。
- 所有复制操作都需要即时反馈，并提示“复制后下一步做什么”。

## 4. 信息架构

建议拆分为以下页面：

| 页面 | 路由建议 | 主任务 | 说明 |
| --- | --- | --- | --- |
| 首页 | `/` | 介绍产品与引导进入技能中心 | 品牌、能力、工作流、推荐技能、快速开始 |
| 技能中心 | `/skills` | 搜索、筛选、发现技能 | 核心流量页，强调高密度浏览 |
| 技能详情 | `/skills/:namespace/:name` | 理解技能并安装 | 展示元信息、版本、扫描状态、AI 安装指引 |
| 发布页 | `/publish` | 发布新技能 | 聚焦上传、填写元数据、发布反馈 |
| 控制台 | `/console` | 管理我的技能 | 聚焦编辑、删除、版本管理 |
| 登录/注册 | `/login` `/register` | 认证 | 独立页面，不与营销内容混排 |

## 5. 全站导航

新增顶部导航栏，建议包含：

- Logo / Brand
- 首页
- 技能中心
- 发布
- 控制台
- 安装指南
- 登录态入口 / 用户菜单
- 全局搜索入口

移动端采用抽屉导航，桌面端采用横向导航。导航需要在全站保持一致，并支持当前页高亮。

## 6. 核心页面要求

### 6.1 首页

- 重构为更紧凑的产品首页，不再承载控制台和发布管理操作。
- 首屏应同时表达三件事：这是什么、能解决什么、下一步去哪里。
- 首页内容建议保留：
  - 产品定位
  - 核心能力
  - 使用流程
  - 推荐技能
  - 快速开始
  - 进入技能中心 CTA

### 6.2 技能中心

- 作为重构重点页面，承担“搜索 + 筛选 + 浏览 + 比较 + 进入详情”的任务。
- 至少支持：
  - 关键词搜索
  - namespace 筛选
  - tag 筛选
  - license 筛选
  - 公开状态筛选
  - 排序：最新、下载量、评分、更新时间
- 建议支持：
  - 卡片 / 列表双视图
  - 最近搜索
  - 空状态引导
  - 热门技能、最新技能、已验证技能快捷入口

### 6.3 技能详情

- 独立承载安装决策，不再塞在列表旁边。
- 至少展示：
  - 名称、命名空间、描述
  - 标签、License、是否公开
  - 最新版本、发布时间、包大小
  - 扫描状态、下载量、评分
  - 版本列表
  - 下载 ZIP 包入口
- 需要增强“可信度表达”，例如扫描状态、更新时间、版本记录、兼容平台。

### 6.4 AI 安装指引

- 作为技能详情页的核心模块。
- 面向不同 AI/IDE 提供分步安装指引，至少优先覆盖 Codex，并预留其它已支持平台。
- 每个方案都需要：
  - 安装前说明
  - pull 命令
  - install 命令
  - skill 引用名
  - 下载链接
  - 一键复制按钮
  - 复制成功反馈
  - “下一步做什么”提示

### 6.5 发布页

- 从首页拆出，聚焦单一任务。
- 上传格式统一为 ZIP。
- 发布表单需要清晰的字段分组、错误提示、成功后的后续动作建议。

### 6.6 控制台

- 作为登录后的管理入口。
- 至少支持：
  - 查看我的技能
  - 查看版本
  - 编辑描述 / 标签 / License / 公开状态
  - 删除 skill
  - 删除版本
- 结构上应强调“列表 + 详情侧”的管理效率，避免长表单堆叠。

## 7. 建议补充项

- 增加 FAQ / 安装前检查，降低首次使用门槛。
- 增加 Breadcrumb，降低多页面切换时的迷路感。
- 增加 Skeleton、Toast、空状态、错误态、重试态。
- 增加相关推荐技能和“同命名空间其它技能”。
- 首页增加“为什么不用 README / 私聊传路径”的对比表达，强化产品价值。
- 增加基础 SEO 元信息和分享卡片，服务宣传场景。

## 8. 技术重构要求

- 前端从单入口大组件重构为路由 + 页面 + 复用组件结构。
- API 层、页面层、展示组件层分离。
- 样式层建立统一 token，不再在单页面里分散堆叠页面级视觉规则。
- 保持桌面端与移动端都可用。
- 不在本阶段引入无关 UI 组件库迁移或依赖升级，除非实施中确有必要并单独确认。

## 9. 后端配合建议

如果要把技能中心做得足够好，建议后端搜索接口后续补强以下能力：

- 多字段筛选参数
- 排序参数
- tag / license / scan_status 维度过滤
- 更明确的分页信息

若后端暂不调整，前端先做结构重构和已有能力增强，但技能中心的上限会受限。

## 10. 分阶段实施建议

### 阶段 1：文档与骨架

- 完成需求规格、执行计划和设计方向文档
- 拆分路由、全局布局、头部导航

### 阶段 2：首页 + 技能中心

- 完成首页重构
- 完成技能中心页面和高密度检索布局

### 阶段 3：技能详情 + AI 安装指引

- 完成详情页
- 完成一键复制和安装引导

### 阶段 4：发布页 + 控制台

- 迁移现有发布与管理能力到独立页面
- 完成整体回归与细节打磨

## 11. 验收标准

- 前端从单页改为多页面结构。
- 顶部导航全站可用，移动端也可访问。
- 技能中心成为独立页面，并具备增强后的搜索与筛选能力。
- 技能详情页具备完整的 AI 安装指引和一键复制功能。
- 发布页与控制台从首页剥离。
- 整体视觉统一为扁平风，信息密度明显提升。
- `npm run build` 通过。
