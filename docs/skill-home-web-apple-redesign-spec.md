# Skill Home Web 苹果风重构设计

## 1. 目标

本轮前端重构不再沿用现有“扁平工具页 + 大量边框卡片”的视觉方向，而是改为更接近 Apple 官网和系统应用的高密度产品界面：

- 更少边框，更多依靠层级、材质、留白和细分隔线建立结构。
- 更高信息密度，但不靠压小字号和挤按钮实现。
- 页面只保留当前任务需要的信息，不展示重复标题、重复提示和重复 CTA。
- 交互优先服务“找 skill、判断是否可信、复制安装、管理发布”四类核心任务。

这份设计将替代旧版 [skill-home-web-redesign-spec.md](/home/zhuyue/code/skill-manager/docs/skill-home-web-redesign-spec.md) 中的“扁平风”视觉方向，但保留其路由拆分和信息架构结论。

## 2. 当前问题

以下问题来自当前实现和实机页面检查，主要参考 [App.tsx](/home/zhuyue/code/skill-manager/skill-home-web/src/App.tsx) 与 [styles.css](/home/zhuyue/code/skill-manager/skill-home-web/src/styles.css)：

- 视觉碎片化严重。`topbar`、`surface-panel`、`metric-card`、`catalog-row__fact`、`detail-fact`、`api-key-card` 等几乎所有层级都画了完整边框，导致页面像“很多白盒子叠在一起”，缺少苹果式的大块分组感。
- 同类文案反复出现。几乎每个区块都有 `eyebrow + 标题 + 描述` 三连，首页又重复出现“快速开始/最短路径/安装说明/FAQ”，信息不够克制。
- 首页主任务不够聚焦。Hero、Quick access、Get started、FAQ 都在解释路径，但没有把“搜索 skill”作为真正的首屏主动作。
- 技能中心信息排布效率低。当前列表行同时包含描述、4 个独立事实框、2 个动作按钮，视觉密度高但有效密度低；在移动端，事实框纵向堆叠，把主要 CTA 挤到更下方。
- 技能详情页版式失衡。左侧标题和描述很短，右侧事实和操作盒子很重，中间留下大块空白，页面看起来像未填满的两栏模板。
- 安装指引重复解释过多。IDE 说明、主命令、3 个步骤、复制后下一步都在解释“如何安装”，信息层次可以合并。
- 控制台和未登录态过度使用“大空白面板”。任务很简单，但占用了整页高度，信息密度偏低。
- 状态反馈重复。既有 `StatusBanner`，又有全局 toast，很多成功/失败信息会重复出现。
- 移动端策略偏被动。大量桌面布局只是简单改成单列，没有针对移动端重新组织优先级。

## 3. 设计原则

### 3.1 苹果风，不是营销大片风

- 以浅色为默认主题，强调精致、克制、可信。
- 不使用厚重描边、纯工具站式矩形卡片堆叠，也不走玻璃拟态和夸张渐变。
- 使用柔和背景层次、细分隔线、轻阴影和更统一的圆角系统。
- 让页面像“产品界面”，而不是“宣传页套后台页”。

### 3.2 最大化有效信息密度

- 优先压缩重复解释，不压缩核心信息。
- 列表优先使用紧凑行布局，而不是为每个字段单独造一个小卡片。
- 元信息尽量并入一行或两行，减少“字段标题 + 数值”小盒子的数量。
- 把次级说明折叠到 tooltip、展开区或二级内容中。

### 3.3 一页一个主任务

- 首页：发现和进入。
- 技能中心：搜索与比较。
- 技能详情：安装决策。
- 发布页：提交新版本。
- 控制台：管理已有资源。
- API Keys：凭证生成与撤销。

### 3.4 反馈要即时，但不重复

- 复制、保存、撤销、发布等瞬时动作统一使用 toast。
- 页面内只保留会影响后续操作的状态块，例如发布成功后的“下一步”或 API Key 一次性 reveal。
- 空状态、错误态都做成紧凑块，不再占整屏高度。

## 4. 新视觉系统

### 4.1 字体

- 去掉当前 `Space Grotesk` 的大面积使用，避免品牌字形和正文风格冲突。
- 改为更接近 Apple 系的系统字体栈：
  - `-apple-system`
  - `BlinkMacSystemFont`
  - `"SF Pro Display"`
  - `"SF Pro Text"`
  - `"PingFang SC"`
  - `"Helvetica Neue"`
  - `sans-serif`
- 标题和正文使用同一套字体体系，只通过字重和字距拉开层次。

### 4.2 颜色

- 背景采用冷白到浅灰蓝的连续渐层，不再让每个块独立“刷白”。
- 主表面使用接近 `#FFFFFF` 的高亮白。
- 次表面使用低对比度浅灰，不通过边框强调存在感。
- 品牌色保留绿色体系，但降低饱和度，让它更像操作色，而不是装饰色。
- 危险、成功、警告状态都采用浅底色 + 深文字，不使用高对比色块。

### 4.3 圆角、边框和阴影

- 圆角统一到三个层级：`12 / 16 / 20`。
- 默认取消大部分 1px 实线边框，只保留：
  - 输入框
  - 分段控件
  - 表格/列表的细分隔
  - 关键状态块
- 卡片层次主要通过：
  - 背景色差
  - 内边距
  - 阴影
  - 细分隔线
- 阴影非常轻，只在悬浮层、导航和主内容分组中使用。

### 4.4 组件材质层级

- `Canvas`：页面背景，无边框。
- `Section`：页面主分组，大圆角、弱阴影，尽量无外描边。
- `Inset Group`：组内列表或表单区域，浅灰背景，依靠分隔线分项。
- `Floating Action`：搜索框、主 CTA、弹出层、Reveal 面板，使用更明确的材质对比。

## 5. 信息架构调整

路由层级保持现有方向，但页面职责收紧：

- `/`
  - 产品入口页，强调搜索和开始使用。
- `/skills`
  - 主工作台，默认进入列表视图。
- `/skills/:namespace/:name`
  - 安装决策页。
- `/publish`
  - 发布页。
- `/console/skills`
  - 我的技能管理。
- `/console/api-keys`
  - API Key 管理。
- `/login` `/register`
  - 独立认证页。

保留现有 `console` 二级路由思路，见 [routes.ts](/home/zhuyue/code/skill-manager/skill-home-web/src/lib/routes.ts)。

## 6. 页面级设计

### 6.1 全局导航

- 顶栏改为单层、紧凑、半透明浅材质的 `AppShell`。
- 左侧只保留品牌和主导航，不再同时展示过长品牌副标题。
- 中间保留一个全局搜索入口，聚焦后直接跳转技能中心并写入查询参数。
- 右侧只保留登录态入口和一个主要操作：
  - 未登录：`登录`
  - 已登录：用户菜单 + `发布`
- 移动端改为：
  - 左：品牌
  - 中：搜索按钮
  - 右：菜单按钮
  - 抽屉里展示导航和账号入口

### 6.2 首页

首页改成“一个 Hero + 两个高密度区块”，不再做四段说明书。

#### Hero

- 左侧：一句清晰定位 + 一个搜索框 + 一个主 CTA。
- 右侧：3 个紧凑状态指标，不使用 4 个独立大卡片。
- 删除当前的 `Quick access` 整段，功能直接并入 Hero 和次级区块。

#### 主内容

- 区块 1：精选技能与最近更新
  - 左：1 个精选 skill
  - 右：最近更新列表
- 区块 2：首次使用
  - 只保留 3 步列表
  - 常见问题收成一个可展开帮助区，默认不全展开

#### 删除项

- 删除首页重复的“打开技能中心/查看热门技能/先看安装页”等同义按钮。
- 删除整段 FAQ 大卡片列表，改成更短的帮助入口。

### 6.3 技能中心

技能中心要从“很多卡片”改为“一个真正可扫描的结果工作台”。

#### 布局

- 桌面端：左侧窄筛选栏，右侧结果列表。
- 移动端：默认只显示结果；点击“筛选”后从底部弹出筛选面板。

#### 筛选栏

- 保留关键词、命名空间、标签、License、排序。
- 默认显示为一组紧凑控件，不再给每组单独大标题。
- “常用标签”保留，但只在有标签数据时显示。
- “在线技能 / 命名空间 / 标签维度 / License”这组统计移到结果头部，不再放在筛选栏里。

#### 结果头部

- 一行包含：
  - 结果数
  - 当前排序
  - 活跃筛选标签
  - 刷新
  - 视图切换
- 不再另起一大段标题说明。

#### 列表行

默认切到列表视图，卡片视图降级为可选模式。

- 第一行：技能名、命名空间、版本、状态。
- 第二行：一句描述。
- 第三行：标签 + 下载量 + 更新时间 + License。
- 右侧只保留一个主动作：`查看详情`
- `复制引用` 改成行内次级图标按钮，避免占据完整按钮位。
- 删除当前四个独立事实盒子 `catalog-row__fact`。

#### 空状态

- 紧凑显示“没有匹配结果”。
- 旁边给出 `清除筛选`，不再使用整块大空白容器。

### 6.4 技能详情

详情页改为“信息左，安装右”的真正决策页。

#### 顶部摘要

- 左侧显示：
  - 技能名
  - 命名空间
  - 一句话描述
  - 标签
  - 最新版本 / 更新时间 / License / 下载量 的紧凑元信息行
- 右侧显示一个粘性安装盒：
  - 下载 ZIP
  - 复制引用
  - 复制安装命令

#### 要删除的东西

- 删除大块留白的双栏 Hero。
- 删除右侧多组小方块式事实卡。
- 删除“复制下载链接”这种低频操作的主露出，收进更多菜单。

#### 安装指引

- 默认只展示当前 IDE 的主安装命令。
- `doctor`、`search`、`pull` 放进“展开更多命令”。
- “复制后下一步”并入展开区底部，不单独占一个提示块。
- IDE 切换保留 segmented control，但改成更贴近系统的胶囊样式。

#### 版本区

- 使用高密度表格。
- 桌面端保留单行表头；移动端改成 definition list，不再把表格简单堆成一列。
- 若只有一个版本，不额外渲染太重的表格框架。

#### 相关技能

- 从大卡片改为紧凑列表。
- 每项只保留名字、命名空间、描述片段、更新时间。

### 6.5 发布页

- 页面只保留一个标题和一句提示。
- 主体为表单，左侧不再常驻两个说明卡片。
- 发布前检查改成折叠式 checklist。
- 发布成功后在表单顶部替换成成功摘要条：
  - 已发布版本
  - 打开详情页
  - 复制下载链接

### 6.6 控制台

- 控制台整体改成更接近 Finder / Settings 的两栏式管理界面。
- 左栏固定宽度，负责：
  - 账号信息
  - 分区切换
  - 当前列表
- 右栏负责当前资源详情和编辑。

#### 技能控制台

- 左侧技能列表改成更紧凑的分组列表，不为每项单独画完整边框。
- 当前选中项用底色和左侧色条区分，而不是高饱和整块背景。
- 右侧编辑区域分为：
  - 基础信息
  - 可见性与状态
  - 版本管理
  - 危险操作

#### API Key 页面

- 默认布局改为“现有 Key 列表优先，生成表单次之”。
- 桌面端：
  - 顶部是列表和统计
  - 点击“新建 API Key”后在右侧滑出表单
- 移动端：
  - 列表为主
  - 新建表单走抽屉或底部 sheet
- `使用规则` 改成一段紧凑说明，不单独占一个大卡片。
- 一次性 reveal 保持突出，但简化为：
  - 完整 key
  - 复制
  - 我已保存
  - 一条最短示例命令

### 6.7 登录 / 注册

- 改成居中单卡片，不再使用宽双栏。
- 只保留必要说明和表单。
- 未登录访问 `/console/*` 时，改为紧凑的登录拦截卡，不铺一整块空面板。

## 7. 交互逻辑重构

### 7.1 搜索

- 顶部搜索与技能中心共用一套状态。
- 搜索提交后跳转到 `/skills?q=...`。
- 页面返回时保留筛选和滚动位置。

### 7.2 筛选

- 所有筛选条件写入 URL query，保证可分享、可刷新恢复。
- 默认显示“有结果影响”的筛选；没有数据的筛选项不占位。
- `重置筛选` 只在存在活跃筛选时显示。

### 7.3 复制动作

- 全部复制统一使用 toast。
- 行级复制按钮改成图标或轻按钮，避免视觉抢主动作。
- 复制后不再在按钮上长期显示额外说明。

### 7.4 反馈

- 成功型瞬时动作只显示 toast。
- 表单错误内联显示在字段附近，同时保留总错误摘要。
- API Key reveal、发布成功、删除确认保留专门界面，因为它们会影响下一步。

### 7.5 危险动作

- 删除 skill、删除版本、撤销 API Key 均使用确认弹层。
- 文案聚焦影响范围，不写泛化安全提示。

## 8. 需要修复的显示和体验问题

本轮实现必须同时收掉以下明显问题：

- 首页顶栏品牌区过密，`Skill Home` 与 `AI skill registry` 在桌面端挤在一行，视觉上像没断开。
- 首页 Hero 右侧 4 个指标块过重，喧宾夺主。
- 技能中心每一行结果被 4 个事实块切碎，扫描路径不顺。
- 移动端技能中心每个 skill 纵向过长，导致主操作落到首屏以下。
- 技能详情页左侧出现大面积无意义留白，标题和元信息没有撑满版心。
- 详情页事实信息用多个小卡分散显示，既浪费空间也降低可扫描性。
- 安装指引区域解释过多，主命令不够突出。
- 未登录控制台页信息过少，但容器高度和留白过大。
- 大量 `empty-panel` 使用虚线边框，会破坏整体产品感。
- 多处 section 都使用“英文 eyebrow + 中文标题 + 中文描述”的重复结构，信息层级过度模板化。

## 11. 验收标准

- 首页、技能中心、详情页、发布页、控制台、认证页统一为同一套苹果风视觉语言。
- 页面主要结构不再依赖大量外描边；视觉层次主要通过材质和分隔建立。
- 首页删除重复说明区块，首屏直接进入搜索或安装路径。
- 技能中心默认列表视图的单条高度显著下降，移动端首屏可看到主要动作。
- 技能详情页消除大块无意义留白，主安装动作在首屏可见。
- API Key 管理页面不再出现“规则卡 + 表单卡 + reveal 卡 + 表格”并列堆叠的碎片化结构。
- 所有复制动作反馈一致，重复状态提示显著减少。
- `npm run build` 通过。
- 关键页面通过桌面和移动端人工回归。
